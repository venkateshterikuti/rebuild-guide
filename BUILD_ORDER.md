# Build order and design decisions

All target paths are in the new project root. Use [FILE_INDEX.md](FILE_INDEX.md) for individual recipes and [INTERFACES.md](INTERFACES.md) for their shared contracts. Work offline with respect to FM. The order below resolves module and data dependencies; it does not require a particular coding agent.

1. **Set the project boundary.** Create package metadata, configuration, root instructions and ignored-output paths. Preserve the no-FM restriction. Locate R1/R2 and copy supplied native files unchanged. The full source ZIP supplies data/configuration as well as Python code; installing the Python package alone is insufficient.
2. **Create deterministic primitives.** Implement `common.py`, package entry points and `catalog.py`. Reject duplicate/non-finite JSON, preserve source evidence and compute stable hashes. Compile the catalog from R1/R2. Implement structural JSON discovery without loan values.
3. **Establish independent XML validation.** Implement `xml_tools.py` with local-only imports and source fingerprint checks. Reconstruct the response entry/wrapper from R4/R5 in a separate tree and copy its seven native dependencies unchanged. Compile locally and record the declaration audit and manifest. Never substitute the request wrapper.
4. **Create the reviewed request rule subset.** Use R1/R2 and the rule-file recipe to identify exactly which requirements were selected. Author the corresponding deterministic assertions and source references. Leave remaining business coverage explicit. Counts are baseline checks, not coverage percentages.
5. **Implement mappings and examples.** Add reviewed profiles, JSON-pointer resolution, supported scalar transformations, ordered/repeated templates and reviewed xlink structure. Build the fabricated synthetic example and its generator. Validate structure and negative cases; do not make the example pretend to be a complete mortgage application.
6. **Add assistance and upgrades.** Implement conservative mapping suggestions, explicit coverage, catalog comparison and mapping/code impact. Suggestions never confirm semantics. Preserve baseline decisions and reject stale profiles. Use an explicitly synthetic target catalog only to test the upgrade mechanism.
7. **Interpret saved exchanges.** Create partial error/vendor references using R3/R6/R7, then implement response analysis and saved-event replay. Keep echoed request, processing state, underwriting results and persistent identifiers distinct. Create synthetic response fixtures; identify them as synthetic.
8. **Implement the application runtime.** Define transport/header/clock interfaces, the specification runtime, SQLite state store and assessment client. Persist intent before delivery, reject duplicate/conflicting operations, apply changing intervals, retain results and support explicit saved-response reconciliation. Do not add real HTTP/authentication code.
9. **Build the simulator.** Implement an in-process service and credential issuer using the document-derived structure. Label credential format/lifetime, interval units, response schedules, identifiers and results as simulation choices. Execute the successful cycle and all fault scenarios without sockets.
10. **Make an actual reference application integration.** Create the initially unconnected pilot application. Add read-only repository inspection, reviewable full-content plans, guarded application/rollback and a Python application-adapter template. The demo copies the pilot, applies five changes, runs its original plus new tests, then exercises the scenario suite and upgrade example.
11. **Expose the workflows.** Implement CLI commands, artifact handoff, language bridges, structured feedback and the shared skill/provider prompts. The skill must produce actual application changes when integration is requested, not stop at generated XML. Avoid executing arbitrary discovered repository commands.
12. **Verify and distribute.** Run behavior-focused tests, compile both schema trees locally, test generated Python templates, validate skill metadata and perform a clean relocation/install exercise. Write current validation evidence only after running checks. Build the allowlisted ZIP and compare hashes. Keep extraction/review/private artifacts outside it.

## Decisions an agent should preserve

- Python is the single deterministic runtime. Java/C# templates invoke it through argument arrays, with no shell interpolation or claimed native networking implementation.
- The assistant determines meaning from client evidence; code implements confirmed transformations. Name similarity never settles role or product semantics.
- Field identity includes context and element/attribute kind. A UID/name alone is insufficient for binding to arbitrary XML paths.
- Native source hashes, catalog identity, selected-rule identity and response-schema identity serve different purposes. An active client transaction also pins its profile and polling policy.
- XML validation and selected business-rule success do not establish service acceptance. Keep the incomplete-coverage signal throughout delivery.
- Recording intake is historical input preparation. No client workflow depends on recording processing or on the original user's filesystem path.
- Instructions alone do not guarantee exact source bytes. See [REPRODUCIBILITY.md](REPRODUCIBILITY.md).
